## 1. 目标与边界

### 1.1 目标

补齐账号安全闭环：**注册邮箱验证 + 找回密码**，打通 SMTP 邮件通道。当前账号一旦忘密码只能靠管理员重置，邮箱也仅是选填资料字段。

### 1.2 本期边界（做什么 / 不做什么）

| 做 | 不做（后续迭代） |
| --- | --- |
| SMTP 邮件通道（Spring Mail） | 邮件营销 / 评论通知订阅 |
| 注册邮箱验证码（发送、校验、限频） | 第三方登录（GitHub/微信） |
| 找回密码（邮箱验证码 + 新密码，成功即踢会话） | 注销账号（v1.6.1 已移入不做） |
| 已登录换绑邮箱（需验证新邮箱） | 站内信 / 私信 |

> 不做 SSR 迁移，SPA 架构内完成。

## 2. 决策点（已拍板）

| # | 决策点 | 选项 | 结论 |

| D1 | 注册邮箱是否改必填 | A 必填 + 必验证 / B 维持选填（填了才验证） | **A**：找回密码依赖邮箱；当前仅少量测试账号迁移成本≈0 |

## 3. 表结构变更

- **D1=A（已采纳）**：`user` 表 **0 处变更**——email 已有唯一约束，注册即验证，无需 verified 标记；存量无邮箱账号保留登录/评论/投稿能力，但无法自助找回（引导联系管理员或登录后换绑邮箱）；
- **不新增任何表**，总表数维持 10 张。

## 4. API 设计（`/api/front/auth` 组扩展，已实现）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | /send-email-code | `{scene: register\|reset\|bind, email}`；限频：同邮箱 60s 1 条、同 IP 每小时 10 条（复用 RateLimitUtil）；**防枚举**：reset 场景对不存在的账号静默成功；register 场景对已注册邮箱直接提示；bind 场景需登录态 |
| POST | /register | body 增加 `emailCode`（必填，服务端校验并消费验证码；放在占用校验之后，前序失败不浪费验证码） |
| POST | /forgot-password | `{email, code, newPassword}`；校验通过重置 BCrypt 密码并 `StpUtil.logout(userId)` 踢会话 |
| PUT | /email | 已登录换绑 `{email, code}`（scene=bind，验证新邮箱） |

> 实现时调整：`PUT /profile` 原本可直接改邮箱，会绕过验证——已将其 email 字段移除，**邮箱变更只能走验证码通道**。

## 5. 安全设计

1. **验证码**：6 位数字，Redis key `blog:email-code:{scene}:{email}`，5 分钟 TTL，校验成功即删；连续错 5 次作废重发；
2. **防轰炸**：发送限频双层（邮箱级 + IP 级），全部走既有 RateLimitUtil；
3. **防枚举**：找回发送对不存在账号静默成功、重置对不存在账号静默成功，不泄露账号是否存在；
4. **会话安全**：重置成功后踢掉该用户全部存量会话（与封禁即踢同管线）；
5. **密码**：强度沿用 6~32 位 + BCrypt 存储。

## 6. 兼容与迁移

- 现有功能（游客浏览/评论、投稿审核、RSS、图床、搜索）零影响；
- 存量账号无邮箱：登录/评论/投稿不受影响，仅自助找回不可用（D1=A 下新注册全部带邮箱，存量自然消化）；
- Nginx / 部署脚本无需变更（邮件为后端出站流量）。
