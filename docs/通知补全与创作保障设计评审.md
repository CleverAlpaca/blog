## 1. 目标与边界

三个「小而实」项：**博主不错过互动**（评论/留言→站内通知）、**创作者不丢稿**（编辑器本地快照）、**文章数据不裸奔**（MySQL 定时备份）。

### 1.2 本期边界（做什么 / 不做什么）

| 做 | 不做（后续迭代） |
| --- | --- |
| 站内通知中心：通知表 + 铃铛未读数 + 独立通知页 | 评论/留言的**邮件**通知（用户拍板：站内即可） |
| 文章新评论（含楼内回复）→ 站内通知**文章作者** | 被回复人通知（v2.1 D2 维持不做） |
| 留言板新留言 → 站内通知**博主（ADMIN）** | 站内信/私信（用户间通信） |
| 编辑器草稿自动保存（本地快照 + 恢复提示） | 云端草稿同步（多端） |
| MySQL 定时备份（脚本 + 计划任务）+ 恢复说明 | 备份上云（OSS 异地容灾） |
| 审核结果邮件通知（v2.1 已上线）维持不变 | GitHub Actions CI |

## 3. 表结构变更（新增 1 张表，总表数 10 → 11）

```sql
CREATE TABLE `notification` (
  `id`          BIGINT       NOT NULL AUTO_INCREMENT COMMENT '通知ID',
  `user_id`     BIGINT       NOT NULL                COMMENT '收件人用户ID（关联 user.id）',
  `type`        VARCHAR(20)  NOT NULL                COMMENT '类型：comment 文章评论 / message 留言',
  `title`       VARCHAR(200) NOT NULL                COMMENT '通知标题（如：你的文章《x》有新评论）',
  `content`     VARCHAR(500) NOT NULL DEFAULT ''     COMMENT '通知摘要（评论/留言内容前 80 字）',
  `link`        VARCHAR(255) NOT NULL DEFAULT ''     COMMENT '点击跳转的站内路由（如 /article/1）',
  `is_read`     TINYINT      NOT NULL DEFAULT 0      COMMENT '是否已读：0 未读 / 1 已读',
  `deleted`     TINYINT      NOT NULL DEFAULT 0      COMMENT '逻辑删除：0 未删 / 1 已删',
  `create_time` DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `update_time` DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (`id`),
  KEY `idx_user_read` (`user_id`, `is_read`)
) ENGINE = InnoDB DEFAULT CHARSET = utf8mb4 COLLATE = utf8mb4_general_ci COMMENT = '站内通知表';
```

## 4. 设计要点

### 4.1 站内通知（评论/留言 → 博主/作者，**不发邮件**）

| 事件 | 收件人 | 通知内容 |
| --- | --- | --- |
| 文章新评论（含楼内回复，D1=B） | **文章作者**（article.user_id） | 标题「你的文章《x》有新评论」+ 摘要（评论前 80 字）+ 链接 `/article/{id}` |
| 留言板新留言 | **博主**（启用中的 ADMIN 账号） | 标题「收到新留言」+ 摘要 + 链接 `/message` |

- 统一护栏：**非本人操作**（自己评论自己文章不通知）；`user.email_notify` 开关与本功能无关（那是审核结果邮件的开关）；
- 站内通知**无需去重**（列表型呈现无轰炸问题，每条互动一条通知）；
- 埋点：`CommentServiceImpl.post`、`MessageServiceImpl.post`，通知写入失败仅记日志不影响主流程。

### 4.2 通知中心（后台 API + 前台两处）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | /notifications/page | 我的通知分页（登录态，按时间倒序） |
| GET | /notifications/unread-count | 未读数（页头徽标；登录时与通知操作后刷新，不做长连接） |
| PUT | /notifications/{id}/read | 单条标记已读 |
| PUT | /notifications/read-all | 全部已读 |

- 前台：页头（登录态）加**铃铛图标 + 未读数徽标** → 点击进 `/notifications`；通知列表点击单条 → 标记已读 + 按 link 跳转；
- AppIcon 新增 `bell` 图标。

### 4.3 编辑器草稿自动保存（纯前端，`/write`）

- 监听标题/摘要/正文/封面变更 → debounce 2s 写 `localStorage`（key 含 `articleId`：新投稿与编辑互不干扰）；
- 进入页面发现同 key 快照且内容≠当前 → 提示条「检测到 HH:mm 的本地草稿」→「恢复 / 丢弃」（D3=B）；
- 发布成功 / 存草稿成功 → 清除对应快照。

### 4.4 MySQL 定时备份（`deploy/backup/`）

- `backup-mysql.bat`：mysqldump 全库 → `backups/blog-YYYYMMDD-HHmmss.sql`（保留最近 30 份自动清理）；
- 附注册 Windows 计划任务命令（每日 03:00）与恢复命令文档；
- `.gitignore` 排除 `backups/`；
- 交付即实测：跑一次备份 + 临时库恢复验证（D4=A）。

## 5. 安全与兼容

1. `backups/` 含全量用户数据（BCrypt 哈希），不入库并标注勿外传；
2. 通知表写入失败仅记日志，不影响评论/留言主流程；
3. 草稿快照仅存本地浏览器；
4. 通知中心为登录态新页面，游客不显示铃铛；不影响既有部署形态。
