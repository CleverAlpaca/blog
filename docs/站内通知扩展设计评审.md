## 1. 目标与边界

v2.2 的通知中心目前只有两类事件（文章新评论 / 新留言）。本期把它扩展成**完整的站内消息体系**：更多通知类型、更强的列表管理、更顺手的入口交互。

### 1.2 本期边界（做什么 / 不做什么）

| 做 | 不做（后续迭代） |
| --- | --- |
| 通知类型扩展：**审核结果站内化**（投稿通过/退回 → 通知投稿者，type=review） | 通知的邮件推送（v2.1 D2 拍板：审核结果邮件保留、其余不发邮件） |
| 通知类型扩展：**评论被回复 → 通知被回复人**（type=reply；仅站内，v2.1 D2 不做的是邮件版） | 点赞通知（toggle 高频反复触发，噪音大于价值，见 §7） |
| 通知中心增强：**类型筛选 Tab**（全部/评论/回复/审核） | 每类通知的独立开关（粒度过细） |
| 通知中心增强：**单条删除 + 清空全部** | 通知回收站/撤销 |
| 铃铛交互升级：**点击弹出最近 5 条下拉预览**（含未读高亮 +「查看全部」） | WebSocket/SSE 实时推送 |
| 未读数**30s 定时轮询**（登录态，路由切换刷新保留） | 通知跳转评论锚点定位（涉及评论渲染时序，本期跳文章页即可） |

## 2. 决策点（待拍板）

| # | 决策点 | 选项 | 建议 |
| --- | --- | --- | --- |
| D1 | 通知类型扩展范围 | **A 审核结果站内化 + 被回复人通知** / B 仅审核结果 / C 再加点赞通知 | **A**：点赞是 toggle（取消也触发），需"仅首次"聚合，噪音大成本高 |
| D2 | 铃铛交互 | A 维持直跳通知页 / **B 点击弹出下拉预览（最近 5 条 + 未读高亮 + 查看全部）** | **B**：主流形态，免跳页看要点 |
| D3 | 未读数实时性 | **A 30s 定时轮询 + 路由切换刷新（现状保留）** / B SSE 长连接 | **A**：单机个人博客无需长连接；SSE 运维/复杂度不成比例 |
| D4 | 通知管理 | A 仅已读 / **B 单条删除 + 清空全部（逻辑删除）** | **B**：通知积累后的基本诉求 |

**0 变更**。`notification.type` 扩展枚举值：`comment` / `message` / **`reply` / `review`**（VARCHAR 无需迁移）。

## 4. 设计要点

### 4.1 通知类型扩展（后端埋点）

| 事件 | 收件人 | type | 通知内容 | 链接 |
| --- | --- | --- | --- | --- |
| 投稿审核通过 | 投稿作者 | review | 「你投稿的《x》已通过审核并发布」 | /article/{id} |
| 投稿审核退回 | 投稿作者 | review | 「你投稿的《x》已被退回」+ 原因摘要 | /my/articles |
| 楼内回复 | **被回复评论的登录用户**（自己回复自己不通知） | reply | 「{昵称} 回复了你的评论」+ 内容摘要 | /article/{id} |

- 与 v2.1 的关系：审核结果**邮件通知保留**（已上线），本期是**加一条站内通知**（双通道并存）；
- 被回复人通知仅站内（无邮件，符合 v2.1 D2 精神）；
- 统一护栏沿用：非本人操作、失败仅记日志。

### 4.2 通知中心增强（前台）

- 通知页顶部加**筛选 Tab**：全部 / 评论 / 回复 / 审核（后端 page 接口加 `type` 筛选参数）；
- 每条通知 hover 出**删除按钮**（逻辑删除）；列表页「清空全部」按钮（二次确认）；
- 铃铛下拉预览：点击铃铛弹出面板（最近 5 条 + 未读高亮 + 单条点击跳转并标已读 + 底部「查看全部」），面板外点击关闭；
- 分页/未读数逻辑沿用 v2.2。

### 4.3 未读数轮询

- `stores/notify.ts` 增加 30s `setInterval` 轮询（仅登录态启动，登出清除）+ 路由切换刷新保留；
- 轮询在页面不可见时跳过（`document.visibilityState` 检查，省请求）。

---

## 5. 安全与兼容

1. 删除/已读接口全部带归属校验（仅能操作自己的通知）；
2. 新 type 值向后兼容：旧通知 type=comment/message 不受影响，筛选 Tab 对未知类型归入"全部"；
3. 下拉预览复用分页接口（pageSize=5），无新端点；新增端点仅 `DELETE /notifications/{id}` 与 `DELETE /notifications`；
4. 通知写入仍为旁路（失败仅记日志），审核/评论/回复主流程不受影响。
